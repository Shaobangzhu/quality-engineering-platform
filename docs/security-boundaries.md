# Security boundaries

Run only owned and audited code at a separately approved SHA. The local Git snapshot provides a separate working directory for ordinary writes. It does **not** enforce OS-level filesystem, network or service isolation. Code and dependencies run with the process's effective OS permissions. Approval covers the test code, configuration and dependencies as well as the commit identity.

- QEP rejects dirty or mismatched sources, unsafe Git metadata and overlapping or symlinked workspace paths. It scans committed paths for conventional credential, dotenv, backup and dependency names and checks tracked symlink targets. A regular `.env.example` is allowed as documentation. Ignored source files stay in the original checkout. The path scan is name-based, so review of committed content remains necessary.
- The runner accepts fixed catalog commands for supported direct Node, Jest or Vitest unit scripts and the exact reviewed DGI workspace chains at their pinned SHA. It rejects unapproved script forms and source lifecycle hooks. The unit scope excludes Docker, persistent MongoDB, browser tests, integration tests and E2E.
- The opt-in source installation runs `npm ci --ignore-scripts --include=dev` inside the snapshot. Third-party `hasInstallScript` metadata is accepted when the lock entry otherwise passes validation. Registry provenance, lockfile integrity, and restrictions on local references and workspace links still apply. Dependencies that need a skipped hook can fail during installation or testing. The runner reports that failure with hooks still disabled.
- npm and the test process receive an explicit environment with a private home, cache and temp directory. Inherited credentials and service configuration are excluded. Child output is consumed in memory, npm debug log retention is disabled and the summary carries bounded status metadata.
- The lock coordinates execution within one QEP installation. Process-group cleanup assumes children stay in that group. A retained lock requires checking that the previous owner and its processes have stopped before recovery.
